# Agents Remember Benchmarks

This directory contains reproducible benchmark fixtures for comparing Codex runs with and without Agents Remember memory.

The benchmark suite is both evidence and a replay harness:

- `cases/` contains manifest files, prompts, and author-provided result reports.
- `templates/` contains generated-workspace templates, including the source-only and memory-enabled benchmark workspace `AGENTS.md` files.
- `workspaces/` is generated by `prepare` and intentionally ignored. Each case workspace has one source-only environment and one memory-enabled environment. The memory-enabled environment has its own `repos/` tree and case-local `ar-coordination/` root where `prepare` clones the pinned external memory repo.
- `user-runs/` is created by the installed runner for local outputs. It is intentionally ignored and preserved across benchmark package reinstalls.

Benchmarks are not installed by default. Install them explicitly:

```bash
python3 agents-remember-md/installer/install-runtime.py ./ar-coordination --include-benchmarks
```

Then inspect or run them from the installed runtime:

```bash
./ar-coordination/scripts/run-benchmarks.py list
./ar-coordination/scripts/run-benchmarks.py prepare case agents-remember-md-drift-workflow
./ar-coordination/scripts/run-benchmarks.py run case agents-remember-md-drift-workflow --dry-run
```

Use `--skill-exposure-mode copy` with `prepare` or `run` when the host cannot
create or follow symlinks. The default `auto` mode first tries the runtime skill
installer and falls back to a copied skill tree when needed. `link` requires the
installer path to work, and `none` skips benchmark-local skill exposure.

## Layout

```text
benchmarks/
  README.md
  cases/
    <case-id>/
      case.json
      prompts/
      author-results/
  templates/
    source-only-AGENTS.md
    workspace-AGENTS.md
  workspaces/                  # generated by prepare, ignored
    <case-id>/
      source-only/
        .benchmark-root
        AGENTS.md              # rendered from templates/source-only-AGENTS.md
        repos/
          <repo>/
      with-memory/
        .benchmark-root
        .agents/
          skills/
            agents-remember-md/ # symlink or copied tree from ar-coordination/skills
        AGENTS.md              # rendered from templates/workspace-AGENTS.md
        ar-coordination/
          AGENTS.md
          memory-repos/
        repos/
          <repo>/
  user-runs/
    <case-id>/<run-id>/
      <prompt-id>/<variant-id>/run-001.{jsonl,stderr,final.md,metadata.json}
```

Do not add a separate `cases/<case-id>/memory/` folder or vendor memory repos into the source package. The case manifest pins the memory repository URL and commit, and `prepare` clones it into the workspace path the resolver uses during the onboarding-enabled run.

Benchmark manifests, prompts, docs, templates, and author reports are the source-side contract. Generated case workspaces and `user-runs/` outputs are resettable or user-generated benchmark state and should stay excluded from Agents Remember onboarding.

## What To Expect

Each prompt has comparable variants:

- `no-onboarding`: Codex works from `workspaces/<case-id>/source-only/` and treats `repos/<repo>/` as source data without an active benchmark memory root.
- `with-onboarding`: Codex works from `workspaces/<case-id>/with-memory/`, where `ar-coordination/` resolves to the cloned pinned external memory and `repos/<repo>/` contains the same pinned checkout.
- `with-onboarding-warm`: when present, Codex starts from the same memory-enabled workspace but treats the benchmark-local memory as already validated, so it can test steady-state memory use without spending the run on startup resolver and drift gates.

The memory-enabled workspace also exposes the benchmark-local Agents Remember runtime through `.agents/skills/agents-remember-md`, so the harness loads the same skills that `ar-coordination/AGENTS.md` references without relying on a parent workspace's `.agents/skills`. By default the runner tries the symlink installer and falls back to a copied skill tree when Bash or symlinks are unavailable; use `--skill-exposure-mode copy` to force the portable path.

Each prompt defaults to three repetitions per variant. For each repetition, the selected variants are placed under the same dated run root and submitted together when the job count allows parallelism. The runner writes raw JSONL, stderr, final messages, metadata, and generated summaries under `user-runs/`.

See [Benchmark Methodology](docs/benchmarks-methodology.md) for metrics, validity checks, and limitations.
