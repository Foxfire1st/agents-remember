# Agents Remember Benchmarks

This directory contains reproducible benchmark fixtures for comparing Codex runs with and without Agents Remember memory.

The benchmark suite is both evidence and a replay harness:

- `cases/` contains manifest files, prompts, and author-provided result reports.
- `templates/` contains generated-workspace templates, including the benchmark workspace `AGENTS.md`.
- `workspaces/` is generated by `prepare` and intentionally ignored. Each case workspace has one `repos/` tree for pinned code checkouts and one case-local `ar-coordination/` root where `prepare` clones the pinned external memory repo.
- `user-runs/` is created by the installed runner for local outputs. It is intentionally ignored and preserved across benchmark package reinstalls.

Benchmarks are not installed by default. Install them explicitly:

```bash
python3 agents-remember-md/installer/install-runtime.py ./ar-coordination --include-benchmarks
```

Then inspect or run them from the installed runtime:

```bash
./ar-coordination/scripts/run-benchmarks.py list
./ar-coordination/scripts/run-benchmarks.py prepare case agents-remember-md-drift-workflow
./ar-coordination/scripts/run-benchmarks.py run case agents-remember-md-drift-workflow --dry-run
```

## Layout

```text
benchmarks/
  README.md
  cases/
    <case-id>/
      case.json
      prompts/
      author-results/
  templates/
    workspace-AGENTS.md
  workspaces/                  # generated by prepare, ignored
    <case-id>/
      AGENTS.md                # rendered from templates/workspace-AGENTS.md
      ar-coordination/
        AGENTS.md
        memory-repos/
      repos/
        <repo>/
  user-runs/
    <case-id>/<run-id>/
```

Do not add a separate `cases/<case-id>/memory/` folder or vendor memory repos into the source package. The case manifest pins the memory repository URL and commit, and `prepare` clones it into the workspace path the resolver uses during the onboarding-enabled run.

Benchmark manifests, prompts, docs, templates, and author reports are the source-side contract. Generated case workspaces and `user-runs/` outputs are resettable or user-generated benchmark state and should stay excluded from Agents Remember onboarding.

## What To Expect

Each prompt is run in paired variants:

- `no-onboarding`: Codex works from the shared source checkout under `workspaces/<case-id>/repos/<repo>/` and prompt only.
- `with-onboarding`: Codex works from the shared case workspace where `ar-coordination/` resolves to the cloned pinned external memory and `repos/<repo>/` contains the same pinned checkout.

Each prompt defaults to three repetitions per variant. The runner writes raw JSONL, stderr, metadata, and generated summaries under `user-runs/`.

See [Benchmark Methodology](docs/benchmarks-methodology.md) for metrics, validity checks, and limitations.
