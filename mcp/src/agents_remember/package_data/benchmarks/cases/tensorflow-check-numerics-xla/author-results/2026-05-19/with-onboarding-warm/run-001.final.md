In TF2XLA MLIR legalization, [legalize_tf_patterns.td](C:/ew/ar-coordination/benchmarks/workspaces/tensorflow-check-numerics-xla/with-memory/repos/tensorflow/tensorflow/compiler/mlir/tf2xla/transforms/legalize_tf_patterns.td:397) has:

```td
foreach src = [TF_PreventGradientOp, TF_CheckNumericsOp] in

```

The StableHLO legalization path has the same pattern. The XLA registry also documents the underlying limitation: XLA does not natively support Assert or CheckNumerics and may cluster them by eliding them in [xla_op_registry.h](C:/ew/ar-coordination/benchmarks/workspaces/tensorflow-check-numerics-xla/with-memory/repos/tensorflow/tensorflow/compiler/tf2xla/xla_op_registry.h:168).

So the safety guard is dropped when the function is compiled through XLA: the op is lowered to its input value rather than to a side-effecting check. A fix would need to land in the XLA/MLIR legalization path, either by lowering `CheckNumerics` to supported HLO/StableHLO constructs with a real failure mechanism, or by rejecting/diagnosing XLA compilation for this op instead of silently replacing it with the input.
