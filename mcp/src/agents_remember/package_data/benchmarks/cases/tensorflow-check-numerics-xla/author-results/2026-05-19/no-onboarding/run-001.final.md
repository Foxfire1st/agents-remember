Triaged against `repos/tensorflow` source only. This is a valid XLA behavior gap, not a Python eager bug.

The source shows `tf.debugging.check_numerics` maps to the TensorFlow `CheckNumerics` op, whose normal CPU/GPU kernels explicitly scan for NaN/Inf and set `InvalidArgumentError` when found:
`tensorflow/core/ops/array_ops.cc:1387`, `tensorflow/core/kernels/check_numerics_op.cc:88`, `tensorflow/core/kernels/check_numerics_op.cc:102`.

Under `tf.function(jit_compile=True)`, the function is marked `_XlaMustCompile` in the Python tracing path:
`tensorflow/python/eager/polymorphic_function/polymorphic_function.py:638`, with the attr name defined at `tensorflow/python/eager/polymorphic_function/attributes.py:64`.

The XLA path is the key boundary. TensorFlow’s XLA registry says Assert and CheckNumerics may be clustered “by eliding them” because XLA does not natively support them:
`tensorflow/compiler/tf2xla/xla_op_registry.h:168`. XLA CPU/GPU/TPU registrations set that elision flag true:
`tensorflow/compiler/jit/xla_cpu_device.cc:79`, `xla_gpu_device.cc:96`, `xla_tpu_device.cc:363`.

The direct lowering confirms the silent pass-through: MLIR TF-to-XLA legalization has:

and rewrites `TF_CheckNumericsOp` to `replaceWithValue $op`:
`tensorflow/compiler/mlir/tf2xla/transforms/legalize_tf_patterns.td:397-399`.

The StableHLO path has the same rewrite:
`tensorflow/compiler/mlir/stablehlo/transforms/legalize_tf_patterns.td:389-391`.

There is also a checked-in legalization test expecting `tf.CheckNumerics` to lower to `return %arg0`:
`tensorflow/compiler/mlir/tf2xla/tests/legalize-tf.mlir:1300-1303`.

Likely cause: when XLA compilation is enabled, `CheckNumerics` is treated as a dummy/no-op operation because HLO/StableHLO has no native runtime error-producing equivalent for it. The normal TensorFlow op is stateful and must execute, but the XLA legalizer discards that checking side effect and preserves only the input value. So the reproducer’s NaN is expected to raise in eager and non-XLA graph execution, but pass through under `jit_compile=True` in this checkout.
