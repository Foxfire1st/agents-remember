**Likely Cause**

`tf.debugging.check_numerics` is compiled away under XLA because TensorFlow’s XLA lowering currently models `CheckNumerics` as identity/pass-through. Since no HLO-side runtime error/check is emitted, NaN/Inf values survive and are returned normally.

**Subsystem Boundary**

Ownership likely spans `tf.debugging` surface behavior, core `CheckNumerics` op/kernel semantics, and mainly `compiler/jit` plus `compiler/tf2xla`/MLIR legalization. The actionable fix would be in the XLA lowering/compilation path: either preserve the check with a real XLA-supported runtime assertion/error mechanism, reject `CheckNumerics` in must-compile functions instead of silently eliding it, or move the check outside the compiled region where normal TF kernels can enforce it.
