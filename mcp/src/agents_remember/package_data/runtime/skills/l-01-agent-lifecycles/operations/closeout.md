# Operation — Authorized Closeout

The Manager or Orchestrator may coordinate an existing AR paired closeout with supplied task authority. In a flat run with neither role, the owning Architect may coordinate the same transaction only when the already-delegated authority of the kept closeout workflow (`../../w-02-light-task-workflow/workflows/closeout.md`) permits it. Carry targeted check results under that workflow's accepted code/memory input; a failure or not-run check stays visible owner evidence and is not replaced by a blanket full-suite gate. Required curation/coherence and real conflict/authority checks still govern the transaction. Requested independent review remains separate evidence. It is never a Worker, Reviewer, or Curator task.

Before calling the existing AR closeout owner, read its current preview and authority contract. Bind the exact code and memory worktrees, canonical task/contract, candidate tips, changed paths, check results, and review/curation reports. Keep failures or missing evidence visible. The owner validates and applies the paired transaction; do not reproduce its logic with raw Git commands.

On converted memory, the closeout preview and apply judge the exact candidate code/memory trees with the invariant gate. Leaf integration judges its closeout pair again. A master or checkpoint landing validates the master's memory commit against the parent line's memory tip and checks that entries at paths in the master's net code diff are current at its code commit. Final master landing proves every non-abandoned leaf landed; a checkpoint proves the chain of leaves already landed. Direct landing likewise judges its exact candidate pair before publication.

A gate refusal prevents publication and names the findings: closeout and integration report `knowledge-gate-refused`; direct landing reports `direct-landing-knowledge-gate-refused`. Send the findings to the Curator for repair, then retry the owning route on the corrected pair. Nothing bypasses the gate. A Manager checks the packet's dependencies before starting and before integrating a leaf, because the product does not.

A finished turn of a role agent is not closeout. No role may claim commit, integration, push, or acceptance until the owning tool's result is read back and the exact code/memory outcome is verified. Human-pinned approvals remain with their named authority.
