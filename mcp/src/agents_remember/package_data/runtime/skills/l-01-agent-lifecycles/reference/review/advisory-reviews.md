# Advisory independent reviews

Architects read this file when commissioning optional advisory Investigators alongside a leaf's normal Reviewer to obtain independent second views of a freeze.

## Advisory independent reviews

### Commission a separate view

An advisory review of a leaf's freeze is an exception to normal routing: the Architect commissions it and carries the findings to the Reviewer. The Manager relays no findings.

The Architect may add advisory reviews when the developer asks or when it judges a second view worth its cost. Any number is allowed, each on any configured provider an installed harness reaches.

Start each advisory Investigator through `role_start` without a task reference. It holds no leaf seat; the leaf keeps its single Reviewer seat.

### Give each Investigator the same material

Provide the freeze, requirement packets, rulings, design source and Worker evidence supplied to the Reviewer. Give each advisory Investigator its own output folder, clean copy for anything it runs, and separate ports.

No advisory reviewer reads the Reviewer's or Curator's files, messages to or from them or the Manager, or another advisory reviewer's folders. Each reports only to the Architect.

Because the Investigator's capsule does not include review operations, the Architect's brief must carry these isolation rules. Name nothing the Architect or developer has already noticed so the comparison stays independent.

### Compare and route the findings

An advisory report changes no verdict by itself; the Reviewer's verdict remains the grade the product reads. Once all reports arrive, compare findings raised by all, some and one reviewer.

Send the Reviewer one questions file containing each finding it did not raise, and tell the Manager once for the gate and the round:

- The questions file asks the Reviewer to rule on each item as on a Curator code finding: take it into its findings and reopen the verdict for that point, or explain why it does not hold. State this duty explicitly in the questions file because the Reviewer and Manager do not read this Architect-only procedure.
- The Manager's notice states that the leaf's next step waits for the Reviewer's rulings and whether the Architect grants an extra round. An extra round for advisory findings is the Architect's grant.
- The Reviewer returns its rulings to the Architect. An accepted finding goes to the Worker as usual. The Architect's pre-landing check confirms that every advisory finding has a ruling.
- The Architect and developer settle disagreements by discussing the findings.

### Account for costs and permissions

Each advisory reviewer consumes its provider's quota and machine memory. Investigator launch choices use admitted `orchestration.roles` settings and applicable `orchestration.rolesPerLevel` overrides.

The Architect sets the mode or runs an approver only within sufficient seat permissions. Before responding to an advisory reviewer's permission prompt, read [Formal permissions](../../operations/orientation.md#formal-permissions) for the once-only developer notice and existing parent route.
