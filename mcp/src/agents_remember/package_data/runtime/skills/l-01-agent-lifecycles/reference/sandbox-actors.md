# Sandbox settings, launch homes and actor starts

Roles setting up or inspecting sandbox actors use this file for per-run harness settings, user-owned configuration boundaries, model selection, launch homes and binding proof. It grants no additional authority.

## Bind sandbox harness settings per run

Do not write user-level harness configuration. Bind each sandbox actor per run, or stop and ask.

## Report a user-level harness configuration file

Leave a user-level harness configuration file that an agent created unchanged and tell your parent, who routes one notice to the developer.

## Use the cheapest model for test actors

Test actors need no extra permission under Agents Remember's rules; a harness's own approval review may still ask the developer. Use the cheapest model of the harness the run is set up for, and name it in the command and the record. Ordinary sandbox isolation applies.

## Keep product settings out of user-owned harness files

The product never edits a harness file the user owns. Ship a setting Agents Remember needs through its own launch settings, or document it on that harness's page.

## Use the sandbox product's launch home

Keep credentials out of a sandbox-local harness home. Run model turns through the sandbox product's launch home.

## Prove sandbox actor binding before launch

Before sandbox actors start, prove their tool-server binding with a stub. Count the host's agents before and after the first `role_start` on `agents-remember-task`.
