# Bootstrap — the knowledge foundation is the Architect's work (step 8)

8. **Report the knowledge foundation's state and hand its making to the Architect.** The
   foundation — the authored records under `knowledge/` in the memory repository, as distinct from
   the onboarding cards and from the baseline — is the curator's procedure, the
   `c-14-knowledge-bootstrap` skill, run inside a task the Architect organises. **This seat reads
   and reports its state; it does not reach it and does not produce it.** Read the state from
   `memory_init`'s `knowledge` block — `not-recorded`, `recorded` at an exact identity,
   `unusable`, or a refused admission with its own next action — and report which of those it is.
   Then tell the user the next step in words they can act on: start the Architect, and it will
   organise memory and knowledge bootstrapping as a regular task, master or sprint according to
   the size of the work, through `c-14`'s Curator route.

   Nothing about that foundation is fabricated here to make a step run: no development leaf,
   worktree or enclosure is created for it, `task_doc` and `role_start` are not called by this
   seat, and no record is written by hand. A repository whose memory has a commit may still show
   `not-recorded` when this seat finishes: that is the honest state of a setup that is complete
   and a foundation that is now the Architect's first piece of work, and the report says exactly
   that rather than claiming the foundation happened.
