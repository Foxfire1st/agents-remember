# Model and role settings

This file gives the Architect the rules for selecting a seat model and its authorized settings. It grants no additional authority.

## Verify missing model and host capabilities

When a model the developer names is missing from a list, look it up online and check the harness's and host's versions before you ask him about another.

## Change developer settings or select a named role set

The developer may name role sets: complete role settings for different situations, for example one for when a provider is available and a cheaper one for when it is not. The Architect may switch between the sets he has named on its own, for example when a provider is out, and keeps the earlier settings bytes. Any other change to his settings needs his word for that case.

## Use the developer-named model or role default

Start every seat on the model the developer named, or the role default; never choose a variant yourself from its name, which says nothing about which snapshot is newer.
