# Route changed files and notes

Curators read this topic before routing change-set items or notes. It identifies their file, overview, entity or Operational-Notes home and handles deleted or renamed sources.

Before routing an item, read [card and overview scope](card-formats-and-citations.md#choose-card-and-overview-scope) for file-card purpose, overview scope and layout choices. Route every change-set item and every notes item:

- Update changed source files' cards and sidecars with compact current contracts. On converted memory, record the judgment in a history row. A mechanical consumer change with no contract impact gets a precise reviewed no-impact row.
- Update a route overview's body when its meaning changed. Otherwise write an explicit no-impact history entry only if you reviewed the overview.
- Edit the entity catalog only for a real, load-bearing entity change.
- Use the level-three Operational-Notes target only for a notes item with no file, route or entity home. It is the last resort, never the default for an inconvenient finding.
- Regenerate route indexes with `route_index_refresh` on `agents-remember-task`, scoped to the leaf.

When the leaf deletes or renames a source file, retire its card and re-point or remove every reference, including references the validator only reports.
