# Child questions, developer answers and instruction changes

Architects, Orchestrators and Managers use this file to answer or relay child questions, return the developer’s words, record instruction and measurement rulings, and preserve permission-notice routes. It distinguishes the parent’s authority from the developer’s words.

## Answer within your authority or relay the question

When a child asks for a developer decision, first check whether the decision falls within your authority. If it does, answer and identify the answer as your own.

Otherwise, pass the question unchanged to your parent. Name the originating role, task and agent identifier, and add your recommendation separately.

Without a parent, ask the developer in your own chat. Name the originating role, task number, what the task does, agent identifier, question and recommendations.

## Return the developer's words

Send the developer's answer to the agent that sent the question. Before composing that return, read [Recognize a relayed developer answer](../../../operations/orientation.md#recognize-a-relayed-developer-answer) for the three required attribution items.

Each parent on the way down passes those three items unchanged. Never present your own answer as the developer's answer or approval.

## Record and deliver instruction changes

A role-instruction ruling names the exact packet or role file and the heading it changes. The owning task lands it through review and curation, not private memory publication.

A measurement text-change ruling names the superseded packet sentence and renews budgets. Landed new wording reaches a seat through a new start or completed reload. Continue only after the reload finishes.

## Keep permission notices on their existing route

Before answering a formal permission prompt, the Architect reads [formal permissions](../../../operations/orientation.md#formal-permissions) for its seat-limited authority and the developer decision route. A child sends to its parent, and the parent relays notices through the existing route. Do not invent a direct developer route for a parented seat.

The parent route applies only when a parent exists. Do not direct a parentless Architect to route a question through itself.

Before sending a question or developer answer to its waiting child, read [message payloads](../../message-handover.md#send-a-message-that-names-the-files) for the sender duty and [full-store receipt handling](../../message-handover.md#handle-a-full-store-refusal) for pending state and the one resend.
