# Curator repository foundation

Curators use this file for a repository's first or resumed knowledge foundation. It defines foundation admission, source scope and reporting; this route authors knowledge, with no onboarding-authoring duty.

## Enter through the real foundation task

Repository foundation is regular task work. For setup’s state report and next step, follow [Name the next step](../bootstrap/foundation-state.md#name-the-next-step). The user-started Architect opens the real foundation task under a master and starts the Curator on that task document. The Curator uses its actual enclosure contract.

Receive the repository identifier, resolved context, scope, sources and current knowledge state. No incidental code delta is required. Onboarding is optional input and never a start prerequisite.

Before authoring the foundation, follow [the curation operation](../../operations/curation.md) for the reconcile, author and check workflow, and author through the writer it names. This foundation procedure authors no onboarding.

An instructed session cannot replace task admission. Report a missing task; never fabricate a task, worktree or enclosure.

## Scope the foundation

Before you research the sources, read [repository research](../repository-research.md) for the reviewed source inventory, the bounded research and the evidence rules.

Inventory only the source areas the task agrees to cover, and the specifications that govern them, at the exact code revision the task binds. Plan coverage around the load-bearing root and area obligations and their realizations, not one record per file: a foundation is a small set of obligations with real anchors, not a transcription of the source tree.

Name each external document with the version or retrieval time actually read. Record a digest or location when you observed one; never invent one, and never imply that a current document supports a claim checked against an older version.

Report the areas you did not examine. A partial run stays partial and keeps a resumable next action.

## Plan and report the admitted work

Read the declared knowledge state and use the admitted authoring routes. Where the developer supplies the commit instruction, keep planning until it is given.

Before you prepare a hand-off list, read [admission of new records](../../templates/curator-handoff-ingestion.md#admission-of-new-records) for the criterion each new record claims and the refusals a list must avoid. Author the records through the writer [the curation operation](../../operations/curation.md) names, and build each hand-off list in the shape [the curator hand-off list template](../../templates/curator-handoff-list.md) owns.

Report partial foundation scope as partial and name the areas not reached.
