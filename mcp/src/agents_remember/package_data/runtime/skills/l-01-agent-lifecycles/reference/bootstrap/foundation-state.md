# Bootstrap knowledge-foundation state

Bootstrap reads this detail before reporting the knowledge foundation and naming the next step. It explains which state to read and what the Architect will organise.

## Read the state

The knowledge foundation consists of authored records under the memory repository's `knowledge/` directory. It is distinct from onboarding cards and the attributed baseline.

Read `memory_init`'s `knowledge` block and report its state:

- `not-recorded`;
- `recorded`, with the exact identity;
- `unusable`;
- a refused admission, with its own next action.

Before acting on the reported state, apply [Bootstrap's boundaries](../../roles/bootstrap.md#boundaries) for its setup-only authority and authoring prohibitions.

## Name the next step

Name one next step in both the conversation and report: start the Architect. The foundation is the Architect's first regular work through the [registered-leaf task route](../../../c-14-knowledge-bootstrap/SKILL.md#who-runs-it). The Curator creates, extends or resumes it inside that task.

A memory repository with a commit may still report `not-recorded` when Bootstrap finishes. Report that setup is complete and the foundation is the Architect's first piece of work; do not claim that Bootstrap created or completed the foundation.
