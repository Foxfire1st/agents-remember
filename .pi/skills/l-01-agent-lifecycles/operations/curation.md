# Operation — Curation

Reconcile three things before writing: current intent (source and existing onboarding), the approved task/requirement and rulings, and the actual candidate/report/review evidence. Work only in the selected memory worktree and update only affected onboarding, route, or entity records. Preserve valid history and code/memory attribution; do not promote an incident or hypothesis to current intent without evidence and authority.

Read the immutable baseline and current candidate with `knowledge_read`/`knowledge_diff` on the `agents-remember-task` tool server before editing. Preserve the baseline. When the task changes invariant, family, realization, or evidence records, write them through the actual `agents-remember knowledge-ingest` curator writer using the supplied producer hand-off; onboarding markdown alone does not replace those records. Read the admitted result back with `knowledge_read` on the same server. Publish the candidate snapshot only when task authority and the writer's publication contract allow it.

Use the scoped AR curation tools of the `agents-remember-task` tool server and their actual schemas. Follow the selected repository's resolved `system/tools.md` for tool commands and scoped checks, and `system/git-workflow.md` for any permitted Git procedure. Run the scoped checks required by the task. Run the full `memory_quality_check` operation only when the task or owner explicitly requests it; when requested, do not substitute a narrower check. When task authority or the returned checklist requires coherence, produce and validate the `curator_coherence` record with its owning operation. Carry failed, blocked, and unrun results honestly; do not invent a blanket zero-finding gate. Verify each output resolves inside the selected memory root.

Report changed paths, the intent/current/implementation reconciliation, full quality/coherence outcomes, and unreconciled facts. Never edit code or task status, run closeout, accept the leaf, or use a shared/global memory root. Curation is evidence for the owner, not a Git or semantic approval. Put questions for the developer in your own chat; message a peer only with `role_message` on `agents-remember-task`, to the parent agent named in the handover or to a role agent of this task.
