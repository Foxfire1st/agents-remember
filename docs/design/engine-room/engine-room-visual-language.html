0How to read this

The engine room renders the git-lifecycle of a worktree as a podracer cockpit: two provider engines per side (CGC, GrepAI), an official-line workspace and a worktree enclosure, branch/commit nodes, conduits between them, and a code↔memory coupler. State is carried by colour and motion, never by chrome — the same geometry means different things in different colours.

The one rule that keeps getting lost:  cyan = the ACTIVE step (the single transaction happening now — it grows in, holds with a travelling dot, then retracts). amber = a SETTLED relationship (done; a plain static line that retracts only when the relationship is terminated). mint = just changed / landed / booted. red = fault or blocked. A line is cyan only while its step is active; the moment it completes it drops to a plain amber line. Dots and arrow-tips ride only the active cyan flow. One exception to "amber = at rest": engines rest green (online/healthy), never amber — amber is for settled relationships, green is a healthy engine.
Motion doctrine. This spec is written in CSS so it opens anywhere and stays readable in a future session. The dashboard itself does not animate in CSS — per the engine-room motion doctrine it uses GSAP timelines (DrawSVG, MotionPath) + Motion (AnimatePresence / layoutId), with CSS for static styling only. Each primitive below lists the value (ease, duration, colour, glow) that transfers verbatim; §11 maps the CSS technique here to the GSAP/Motion API in the React code.

Reduced motion. Every animated primitive must freeze to its end-state under prefers-reduced-motion: reduce (GSAP matchMedia) — drawn lines rest fully drawn, packets hide, surges stop. Motion is never required to read state; colour alone is sufficient.

1State colours

Five state colours plus two neutrals. Every recolour crossfades over .45s ease (the global ease on stroke/fill). Values are OKLCH — copy them verbatim.

2Lines & conduits

Four line types. They are not interchangeable: the colour and whether it moves is the meaning. Only the active flow is animated; everything else is a static wire.

active flow

Active flow

The one transaction happening now. Grows source→tip, holds while a glowing dot travels, then retracts tip-first. Exactly one is "on" at a time.

cyan draw-in .55s · (.25,1,.4,1) retract .5s · (.5,0,.7,1) dot 1.4s linear glow line 3px · dot 5px width 2.4 · arrow-tip yes
settled wire

Settled wire

A relationship that is done and at rest. Static, no dot, no arrow-tip. It only animates once — retracting — when the relationship is terminated (§9).

amber width 2 opacity .8 no glow · no tip · no dot
planned

Planned / not-yet

A relationship that will exist but is not on disk yet. Dim and dashed. Fades up to a settled wire (or a cyan flow) when it materialises.

dim dash 9 7 opacity .55–.7
blocked

Blocked

A relationship held by a gate. Steady red — never flicker. (Flicker means a fault, §6 — keep "you must choose" visually distinct from "something broke".)

red steady (no anim) width 2.4

3Nodes & boxes

A node is a commit/branch box. Emphasis is event-driven — a box highlights when its state changes, never as a perpetual pulse. The fresh state is the eye-grabber: mint stroke + 4px glow + the hash text recolours.

4Glow scale

Glow is filter:drop-shadow only (GPU-cheap, colour-tintable) — never an SVG filter graph. Blur radius scales with importance, and the glow colour always equals the element's state colour, so glow doubles as a state signal.

structural bar 2px active line / node 3–4px packet / power-up 5px alarm gate 7px colour = state colour

6Engines

A provider engine (CGC / GrepAI). A constant gold bezel frames it — flat, no glow (the glow scale, §4, is reserved for the active body + the fault halo, never the frame). The body (fills from the middle outward to full turquoise, then flashes up and dims to green) carries the runtime colour; the spine and the fanned flank petals are constant gold structural line-art (only their presence varies — an off engine fans no petals). A healthy engine rests green — not amber, not a bottom-up fill. Faults pulse gently (a red body + halo); a re-index pulses amber.

boot — loops

Boot → ready

Dormant → charge fills from the middle outward (scaleY from centre) to full turquoise → flashes up → dims over to green. No amber.

fill center-out 1sflash & dim 1.15srests green
ready / nominal

Ready / nominal

The resting healthy state — steady green, full charge. This is where a booted engine stays (like the dashboard CGC / GrepAI at rest).

green steadyno pulse
fault — gentle pulse

Fault

Backend unreachable / crash-loop. Whole-silhouette red gentle breathe (~1.7s ease-in-out) — never a harsh strobe. Still clearly distinct from a steady block.

redbreathe 1.7s ease-in-out
reindex — gentle pulse

Re-indexing

Recovery work in progress. Amber gentle pulse (breathing) — work is happening, nothing is broken.

amberbreathe 1.6s ease-in-out
Scanlines are not the engine. The fine horizontal grain over the live engines is a global CRT scanline overlay riding above the whole canvas (cockpit atmosphere) — the engine glyph owns only the 7 thick dividers, never baked-in scanlines. The overlay is repeating-linear-gradient(0deg, scan 0 1.5px, transparent 1.5px 4px) at low opacity, applied canvas-wide above every glyph — not per-element.

7Coupler / warp-core

The code↔memory coupler is the memory.md ledger link — it binds this side's code commit to its memory commit. A thick amber bar with a chain-link glyph (two interlocking rings) at its core; when bound it brightens (opacity .3→1) and pumps a bidirectional white energy surge from the link. The dashboard's chain-link is the better version over the mockup's plain bar + ladder + square node. (A bare line/arc in this gap is what produced the "mystery triangle".)

bound — loops

Coupler (bound)

Binds code (top) and memory (bottom) — the ledger row. 9px amber bar with the chain-link core; when bound it brightens and a near-white surge splits up & down from the link. (The ribbing you see live is the global scanline overlay, not the bar.)

bar 9px amber roundchain-link 2 ringssurge 1.6s bi-dirbind opacity .3→1
unbound

Coupler (unbound)

Present but not bound — the bar + link dim to opacity .3, no surge. (Fully absent before the worktree materialises = opacity 0.)

opacity .3no surge

8Choreography — the eye-leading principle

The single biggest "leads the eye" device: within one phase, paired elements are staggered 300–650ms — draw the conduit, then light its target box, then the next conduit. Never light two things at once. The result is exactly one focal point moving through the scene.

staggered phase — loops
flow A draws t=0 box B fresh +550ms flow B draws +1100ms box C fresh +1650ms one focal point at a time

9Retract & despawn

Things leave as deliberately as they arrive — they never blink out. A terminated relationship retracts (the active flow's reverse, §2); a disposed node dissolves (fade + slight scale-down). At teardown the whole worktree side de-materialises as one coordinated power-down: engines → nodes → border → landing tier, nothing lingers.

node dissolve — loops

Dissolve

Disposed node fades and scales to .94. Never a hard pop.

opacity+scale .6s easescale → .94
line retract — loops

Relationship retract

When a settled relationship is terminated the wire retracts (source→tip) instead of dangling. Same dashoffset mechanic as the active flow, in amber, no dot.

retract .5s · (.5,0,.7,1)no dangling lines

10Failure modes

When the lifecycle can't just proceed it blocks, gates, and recovers — or terminates. The prototype (podstage.html) ships eight such scenes; this section pins the shared primitives they draw with, added as each mode lands in the dashboard. Doctrine throughout: a block is steady (a choice you must make — steady red, §2) while a fault flickers (something broke — §6); the two must never look alike. Most modes are recoverable (verify → block → gate → recover → settle); a few are terminal (the integration-conflict STOP) or dissolve away (abandon, §9).

Mode 1 — memory / ledger block (T3b). The first recoverable mode lands the two primitives below. After the code lane is real, the ledger gate verifies the memory side; on a dirty / no-ledger-map / missing memory repo the memory lane is gated while the code lane stays solid, then reconciliation clears it and the memory worktree materialises + the coupler binds (§7). The block itself reuses the steady gate (§2 Blocked) + the attention badge + recovery chips; the net-new pieces are the scan ring and the ghosted lane.
scan ring — loops

Scan ring · preflight verify

Before a gate decides — a ledger-map check, a stale-base preflight, a provider-config probe — a cyan ring expands and fades on the lane being checked. Transient: it plays while the check runs and is gone the instant it resolves (pass → the lane proceeds; fail → the gate drops, §2). Cyan because a check is the active step.

cyan expand+fade ~1.2s ease-out glow 4px transient · freezes (reduced-motion)
ghosted lane

Ghosted lane · one lane held

When one lane is gated while its sibling proceeds, the held lane dims + desaturates so "this side is blocked, that side is fine" reads at a glance (e.g. the memory/ledger block: the code lane stays a solid wire, the memory lane ghosts under a steady gate). Distinct from planned (dashed grey, §2): a ghosted lane is real but held, not not-yet.

opacity .32 grayscale .45 pairs with the steady gate (§2 Blocked)
Mode 2 — stale-base block (T1b). Before the worktree forks, a preflight checks the base: the scan ring (above) sweeps the code/main lane — "is local main current with upstream?". On a behind / diverged base a fleeting enclosure is born blocked (§2.1 provisional — the contract isn't written yet) with the stale main node pruned (the §3 dormant register) and two choices: fast-forward or proceed-stale. Fast-forward advances the base and the worktree boots normally (the recover runs the provider clone, like the boot). Net-new vs mode 1 is only the pruned node on the base — the scan ring (§10), the fleeting block (§2.1), the steady gate (§2) and the recovery chips already exist.

11Timing & easing reference

Pacing is cinematic, not snappy: entrances decelerate (arrive softly), exits accelerate (leave quickly), ambient loops run ~1.4–1.6s under the discrete beats so the scene is never frozen. Copy these verbatim.

Caption legibility rule. Functional text must clear WCAG AA — body ≥4.5:1, large/bold ≥3:1 — against the canvas background (oklch(0.15 0.02 250)). Muted captions sitting directly on the dark canvas (e.g. a "closeout order" label) must use at least --muted oklch(0.74 0.03 250) (≈6:1), never a dimmer token. Faint blueprint decals are decoration, not text to read; keep them clearly below the legibility floor so they never compete with real labels.
