# Operation — Orientation

Start from the role and exact canonical assignment supplied by the launcher. Projects altitude is an execution location, not a repository identity. A taskless Architect or System Specialist uses the developer's request and asks for a missing outcome/repository/concern; do not invent a task or trust packet.

For existing work, recover canonical task status, decision log and rulings, approved requirement versions, prior approvals, role agent IDs, and reports before planning or acting. Continue inside that recorded authority without requesting the same approval because a session restarted or compacted. Only new scope, a changed requirement, or an actual human-pinned decision returns to the developer.

For a task-bound launch, read only the selected requirement packet and task document needed for this assignment. Use each supplied `taskDocReadArgs` unchanged (`repo_id`, `task_name`, extensionless `slug`, `operation=get`) and read canonical JSON at the returned `docPath`. Do not add `.json`, read every parent/child document, or load other role/core files. Confirm the role, task, requirement ID/version, workspace altitude, code/memory roots, contract, and report path agree. A parent agent is optional: a role started from the dashboard has none and needs none, and the developer reads and answers in your own chat. Missing task facts are reported with their owning document and exact field.

Leaf roles work in the exact AR-paired enclosure: code is the Worker write area, memory is read-only for Worker/Reviewer and writable only by Curator, and the task report stays at the canonical path. Projects roles stay in Projects and do not infer a registered repo from its workspace name.

Paseo is the host. Call AR tools only on the tool server named `agents-remember-task`. Find its tools by the server's name, spelled `agents-remember-task` or `agents_remember_task`: declared under a prefixed name, or listed in your harness's own instructions behind its tool search or script tool. A tool that lists or proxies tool servers is not the way to AR tools unless it lists `agents-remember-task` itself: do not search or describe AR tools through it, and take its "server not found" as that tool's answer only. Do not connect to, list, describe or call a server named `agents-remember` or any of its tools: it belongs to another installation. A tool server can take some seconds to appear after a start or a resume: wait a few seconds and look once more before you report it missing. Your tool server's binding is your identity; the handover names your parent agent when you have one. Never invent or replace an agent ID. Put questions for the developer in your own chat; peer questions and results go through `role_message` on `agents-remember-task`. A message another agent sent you begins with a `From` line: your reply in that turn is what the sender receives, so answer it there.

After compaction or reconnect, restore the same role, task, agent IDs, and report from the handover artifact and durable records. Inspect current AR state before acting. Do not repeat a completed action or create a second owner because context was shortened.
