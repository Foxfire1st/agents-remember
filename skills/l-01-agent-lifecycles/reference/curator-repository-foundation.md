# Curator — repository knowledge foundation

**Repository foundation is regular task work.** After setup reports memory/baseline state, the user starts the Architect, which opens the real foundation task under a master. Start this seat on that task document and use its actual enclosure contract. Receive the repository id, resolved context, scope, sources and current knowledge state; no incidental code delta is required. Run `c-14-knowledge-bootstrap`. Onboarding is optional input, never a start prerequisite; this foundation procedure authors no onboarding.

Without a task, Bootstrap reads and reports state and names the user-started Architect as the next step. No instructed session substitutes for task admission. Report a missing task; never fabricate a task, worktree or enclosure.

**For repository foundation:** read the declared knowledge state; use the authoring routes and task admission above. Never fabricate a leaf, worktree or enclosure; where the developer supplies the commit word, plan until given. Report partial foundation scope as partial; name unreached areas.
