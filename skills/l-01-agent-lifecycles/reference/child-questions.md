# Questions received from children

## Relay the question and return its answer

When a child sends a question requiring the developer, answer it yourself if it lies within your authority and say that the answer is your own. Otherwise pass the question unchanged to your parent, naming the originating role, task and agent ID; add your own recommendation separately. Without a parent, put it to the developer in your own chat, naming that role, task number and what the task does, agent ID, question and recommendations. Send the developer's answer to the agent that sent the question: state that the developer gave it, your agent ID as the agent that received it, and the developer's words in quotation marks. Each parent on the way down passes these three unchanged. An answer of your own is never the developer's answer or approval.

A role-instruction ruling names the exact packet/role file and heading it changes; owning task lands it through review/curation, not private memory publication. Measurement text-change rulings name superseded packet sentence and renew budgets. Landed new wording reaches a seat by new start or completed reload; continuation follows completed reload.

D228 formality handling is Architect-owned only within its own sufficient permissions: default/auto-review or refusal means user decides, prompt named once, no bypass. Child sends parent, parent relays notices by existing route; no fabricated direct developer route for parented seats. The parent-route instruction applies only where a parent exists; it must not order the parentless Architect to route a question through itself.

When a question or developer answer is ready for its waiting child, use [message handover](message-handover.md) for the sender duty and receipt handling.
