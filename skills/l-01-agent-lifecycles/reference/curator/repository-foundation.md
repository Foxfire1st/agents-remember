# Curator repository foundation

Curators use this file for a repository's first or resumed knowledge foundation. It defines foundation admission and reporting; this route authors knowledge, with no onboarding-authoring duty.

## Enter through the real foundation task

Repository foundation is regular task work. For setup’s state report and next step, follow [Name the next step](../bootstrap/foundation-state.md#name-the-next-step). The user-started Architect opens the real foundation task under a master and starts the Curator on that task document. The Curator uses its actual enclosure contract.

Receive the repository identifier, resolved context, scope, sources and current knowledge state. No incidental code delta is required. Onboarding is optional input and never a start prerequisite.

Before authoring the foundation, follow [the knowledge-bootstrap workflow](skill://agents-remember/skills/c-14-knowledge-bootstrap/SKILL.md). This foundation procedure authors no onboarding.

An instructed session cannot replace task admission. Report a missing task; never fabricate a task, worktree or enclosure.

## Plan and report the admitted work

Read the declared knowledge state and use the admitted authoring routes. Where the developer supplies the commit instruction, keep planning until it is given.

Report partial foundation scope as partial and name the areas not reached.
