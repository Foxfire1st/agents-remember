# Read governing documentation and preserve decisions

Curators read this topic before explaining an assigned contract or recording a governing decision. It describes selecting and inspecting governing documentation, durable decisions, task-only decisions and rejected alternatives.

## Read governing documentation

Before explaining an assigned contract, inspect the relevant documentation declared in the resolved `system/sources.md`, including its Domain Documentation entries. Open the actual documents and check how they govern the explanation. A registry entry is a pointer, not evidence that its claim is true; name any required source you could not read. This selects evidence for the assigned work, not a repository-wide documentation pass.

## Preserve governing decisions

On converted memory, turn each developer ruling and requirement-packet choice that still constrains code into a decision record with the alternatives it weighed. Decisions that matter only within the task stay in the task. Before authoring the decision record, read [decision-record fields and rules](../../templates/curator-handoff-ingestion.md#decision-records).

Before recording a rejected simplification or workaround, read [the writer's input sections](../../templates/curator-handoff-ingestion.md#the-writers-input-sections) for the current chosen design, rejected option and reason, and the boundary with unfinished work.
