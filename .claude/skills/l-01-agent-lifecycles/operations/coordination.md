# Operation — Coordination

Paseo runs the role agents; you start and reach them through two tools on the `agents-remember-task` tool server: `role_start` and `role_message`. Bind each started role to its exact canonical AR task and requirement. Your tool server's binding names you as the sender and as the parent. Address only agents these tools returned or resolved; never invent a recipient.

Choose a flat graph for small work: Architect directly assigns distinct Workers, Reviewers, and Curators. For a larger sprint, an Orchestrator may coordinate; a Manager may own one selected master. These roles are optional according to scale.

For each distinct role assignment, call `role_start` on `agents-remember-task` with the role, the exact canonical sprint, master, and leaf references its class requires, and a request ID you choose. One call resolves or creates the AR paired enclosure, writes the complete role handover beside the task report, records the launch, and creates the agent in Paseo with you as its parent; the agent starts its assignment at once. It returns the agent ID, report path, handover artifact path, and status. Who may start what: an Architect every role except Architect; an Orchestrator Manager, Worker, Reviewer, and Curator under its own sprint; a Manager Worker, Reviewer, and Curator under its own master; the other roles none. If it answers `unknown`, call it again with the same request ID: that reconciles the same agent and never creates a second. A refusal names the rule or reason; do not work around it.

A leaf role runs in the AR paired enclosure the start resolved; never ask Paseo to create a Git worktree for an AR leaf. Keep the returned agent IDs, report paths, and handover artifact paths with the exact task references in your durable handover.

After a Reviewer rejects a candidate, continue with the same Worker: send it one `role_message` on `agents-remember-task` that identifies the exact finding IDs and report path. Keep the same candidate class and contract baseline, and verify each finding. Start distinct Reviewer and Curator agents for their work. Keep paired code/memory/report paths and exact task references in every message.

Send one message to one agent with `role_message` on `agents-remember-task`, addressed by agent ID or by role plus task references. A role that matches several live agents is refused with their IDs; choose one by ID. A recipient that is mid-turn takes the message up without its turn being cancelled, or the call is refused as busy; a closed session is resumed first; an archived or missing agent is refused and stays as it is. With `wait` the call returns the recipient's final text, a pending permission, or a timeout with the message still delivered; if your own tool calls are cut off earlier than the wait, pass a shorter `timeout_seconds`. Follow your assignments until the work is complete, blocked, or a true developer decision is needed; do not start a role and stop. On a refusal or an uncertain result, act on the named reason; do not guess a parent or start duplicate work. A role started from the dashboard works directly with the developer and needs no parent.

Re-evaluate work from canonical AR task facts and actual evidence when invoked. Do not create background polling or a second scheduler. An agent's turn or status in Paseo is execution metadata, never a second requirements, review, curation, or acceptance ledger.
